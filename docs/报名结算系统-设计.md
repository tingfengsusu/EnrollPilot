# 报名结算系统设计（飞书）

> 状态：**设计中，字段已按真实样表定稿**（旧表实测见 2.0；工种/培训类型等字典值域待归一化）。
> 定位：FormPilot 第二业务场景（安全培训报名管理），面向「飞书售前解决方案」类岗位的可演示案例。
> 对应能力点：多维表格 API、机器人长连接、工作流自动化、（P2）智能体问答。
> 合规边界沿用 FormPilot：只走官方 API，**绝不 hook 个人微信**。

---

## 一、目标与原则

把「前台微信收图 → 手工攒 Excel → 群里口头改状态 → 月底人工对账」换成一条自动链路。

三条设计原则：

1. **双入口，一个库**：入口可以有多个（群机器人 / 桌面剪贴板工具），数据只有一份（飞书多维表格）。本地 Excel 不当主库。
2. **微信只做"人肉搬运一步"**：照片在微信里，复制或转发一下就进系统，其余全自动。
3. **OCR 不确定的不猜**：识别存疑的字段回群/回面板要人确认（沿用 FormPilot「未命中不猜」）。

系统优于原流程的三个点（演示叙事主线）：

- **集团/分公司维度**：公司表挂集团，单张 Excel 结构上做不到；
- **状态变更有入口有审计**：群里一句话/点按钮，谁改的、从什么改成什么、因为什么，全程可追溯；
- **结算自动核对**：收款数据进来就核（缴费 = 公司收费 + 返还），差异当天暴露，结算单一键出。

## 二、数据模型（多维表格五张表）

### 2.0 旧表实测（设计依据，来自真实样表）

样表：`业务员A报名人员.xlsm`（业务员个人维护，总表 516 人）+ `某集团培训26.6.24开票明细.xlsx`。
证实的事实与痛点：

- **钱是四列**：`缴费`（学员实付）、`交公司费用`（上缴全额）、`公司收费`（公司留存报价）、
  `返还`（业务员/渠道分成）。样例：缴费 700 = 公司收费 400 + 返还 300，交公司费用记全额 700；
  退训记录为全额上缴又全额返还。→ 资金口径是「**全额上缴 + 返还**」，见 5.1。
- **凭证图片嵌在单元格**：身份证正、一寸照、学历、缴费截图用 WPS `DISPIMG` 内嵌，
  无法批量取用，换电脑就丢 → 系统里全部改 **bitable 附件字段**。
- **公司名写法漂移**：`某集团(柴油机)` / `某集团（中小拖）` / `某集团收获机具公司`
  （括号全半角、简称、全称混用）→ 公司表枚举 + 集团单选的必要性实锤。
- **日期格式混乱**：总表 `报名日期` 是「6月23日」文本，名单表是 datetime → 系统统一日期类型。
- **学历有两列**（J 列基本信息、R 列材料状态），同名列不同义 → 系统里拆成「学历」+「材料清单」。
- **三张手工衍生表**：`6.24结算`（按期结算单）、`某集团报名人员名单`（按集团筛选）、
  `某集团未参加培训人员`（报了没来）→ 全部改为**视图/导出物**，不再人肉维护。
  「未参加」的存在说明报名与参加是独立维度 → 状态机用三维度（见 2.1）。
- `是否开票` 列 + 结算单按期出（6.24）→ 开票状态进模型，结算单成为导出物（5.3）。
- 某集团协议价 600/人（≠ 散户价）→ `公司收费` 逐单记录，不同客户不同价是常态。
- **微信识别实测**：微信「复制图片内容」输出字段交错错位（"出生 1992 / 民族汉 / 年1月18日"、
  户籍码被折进住址）→ 可用但必须过 LLM 清洗；入口B 做双模式：剪贴板是**图片**走自家
  OCR+LLM，剪贴板是**文本**直接走 LLM 清洗结构化。

### 主表结构：一年一张，按天看

「**报名表（2026）**」是唯一主表，`登记日期` 是普通字段；"每天的报名表" =
按 `登记日期` **分组的视图**（天/月各一个视图），不再每天建新 Excel 文件——
数据永远不合并，跨天统计天然支持。跨年时复制表结构开「报名表（2027）」归档。

### 2.1 表①报名记录（主表）

| 字段组 | 字段（旧表列 → 系统字段） |
|---|---|
| 基本 | 姓名 / 身份证号（`身份证`，校验位校验复用 batch 基建）/ 手机号（`联系方式`）/ 学历（单选）/ 出生日期 / 住址（身份证抽取）/ 参加日期 / 复审到期日期 |
| 组织 | `企业名称` → `公司`（关联→公司表）/ `集团`（经公司表 lookup） |
| 业务 | `班期`（关联→班期表，暂以 `参加日期` 代）/ `安全员/负责人` → 人员类别（单选：主要负责人/安全员/管理员…）/ `工种`（单选+别名归一化）/ `培训类型`（单选：新办/复审…）/ `外省证明`、`危化承诺书` → 材料清单（复选框） |
| 三维状态 | **报名**：待确认→已确认→已参加/未参加；**缴费**：未收→部分→收齐/已退（机器人按收款流水写回）；**开票**：未开→已开（`是否开票` 列） |
| 金额 | `公司收费`（逐单，协议价因客户而异）/ `总报价` / `分成方式`（比例% 或固定额）/ `分成值` / 机器人写回 `累计收款`、`返还` |
| 附件 | `身份证正`、`一寸照`、`缴费凭证` → bitable 附件字段（替代旧表 DISPIMG 内嵌） |
| 来源 | `报名日期` → `登记日期`（统一日期类型）/ `登记渠道` / 来源照片附件 / `合并次数` |

**幂等与合并**：幂等键 = 身份证号（缺则 姓名+手机号归一化）。同一键的多张照片
（身份证一张、报名表一张）合并进同一条记录并 `合并次数 +1`；跨登记日期的同键
记录视为同一人不同班期，由班期关联区分。OCR 字段机器可合并补全；**三个状态字段只允许人改**。

### 2.2 表②公司表（枚举表）

公司全名 / 简称 / **`所属集团`（单选，如"某集团集团"）** / 结算方式（对公 / 业务员代收）/ 协议价（选填）/ 联系人。

- 单选列起步，够做"按集团分组、筛选、出汇总"；集团本身出现属性需求再升级关联表。
- 解决痛点（旧表实证）：`某集团(柴油机)` / `某集团（中小拖）` / `某集团收获机具公司`
  是不同公司（枚举防写法漂移，括号全半角也要归一），同属某集团集团（单选列给维度）。
- 旧 Excel 的公司清单一次性导入这张表（迁移演示点）。

### 2.3 表③班期表（独立，消息提醒的挂点）

班期名称 / **`考试日期`（衡量标准）** / 起始日期 / 结束日期 / 课程 / 状态（筹备→报名中→已开班→已结束）/ 名额 / 负责业务员。
报名记录关联班期。**已确认独立成表**——多期培训按期报名；**提醒以考试时间为准**
（考试前一天发名单提醒），起始/结束日期保留作排期展示。

### 2.4 表④收款表（流水，一笔一条）

时间 / 金额（`缴费`，学员实付）/ 收款方式（微信 / 支付宝 / 对公 / 现金）/
**`收款人类型`（业务员代收 or 公司直收）** / 业务员（人员字段；旧表文件名即业务员，
如「业务员A报名人员」——系统里一个库装所有业务员）/ 关联报名记录（**多选**，支持一笔款多人拼交）/
`缴费凭证` 附件（群里的截图直接挂）/ 备注。
退款用负数流水，不删记录。旧表 `缴费凭证` 列还有纯文本标记（如公司名"发恩德"表示统一付款），归入备注或公司直收标记。

### 2.5 表⑤变更日志（只追加，永不修改）

| 字段 | 说明 |
|---|---|
| 关联报名记录 | 关联字段 |
| 时间 / 操作人 | 飞书用户自动带出；桌面工具操作记工具账号 |
| 变更类型 | 状态变更 / 字段补全 / 照片合并 / 修正 / 退款 |
| 字段 + 旧值 → 新值 | 「待缴费 → 已缴费」 |
| **触发来源** | 群指令原文 / 卡片按钮 / 桌面工具补全 / 机器自动合并 / 结算修正——"因为什么而修改" |

> 多维表格原生修订历史 API 拿不到，审计自建。（表⑥集团表为远期升级，本期不做）

## 三、报名链路（双入口）

```
入口A（主，无人值守）：微信照片 →（转发）→ 飞书群 → 机器人收图+下载附件（gateway/ 复用）
                      → OCR/LLM 抽取 → 写/并 报名记录 → 群里回执卡片
入口B（补充，前台在场）：微信里复制图片 → 打开桌面工具 → 自动读剪贴板 → OCR 抽取
                      → 字段面板人眼预览 → 一键入库（同一张报名表）
```

### 入口A：群机器人

- 长连接事件订阅收消息 + 附件下载 + 多事件合并窗口，全部复用 `gateway/`
  （飞书文本+图片是两条事件，`merge_hold_seconds` 窗口凑齐再建任务）。
- 身份证照片走已有 `sources/` OCR；报名表照片的字段抽取走 LLM 通道
  （`llm/` 网页版 DeepSeek），字段清单与映射 **【待补：等样图】**。
- 回执："张三 已登记 ✓"或"身份证号第 X 位存疑，请确认"（不猜原则）。

### 入口B：桌面剪贴板工具（exe）

FormPilot GUI 的**精简入口**，不是从零新做（Phase 2「拖图识别回填」已存在），增量三件：

1. **剪贴板监听（双模式）**：启动读一次 + 运行中持续监听（PyQt5 QClipboard，无全局钩子）——
   剪贴板是**图片**走自家 OCR+LLM；是**文本**（微信「复制图片内容」的产物，实测字段交错错位）
   直接走 LLM 清洗结构化；
2. **落库目标换成报名表**：`登记日期` 默认今天、`登记渠道`=桌面工具，写 bitable；
3. **PyInstaller 打 exe**：不背 Playwright 依赖，体积可控。

写失败/断网 → 本地 SQLite 队列暂存，恢复后补写（orchestrator 队列思想，MVP 可后置）。

## 五、结算与报告

### 5.1 资金流与分成（已按真实样表修正：全额上缴 + 返还）

```
学员实付「缴费」700
   ├─ 全额 700 上缴公司（旧表「交公司费用」= 缴费全额）
   │     ├─ 公司按「公司收费」400 留存（某集团等协议客户另有协议价，如 600）
   │     └─ 返还 300 = 缴费 − 公司收费 → 返给业务员/渠道
   └─ 退训：全额上缴又全额返还（两条流水自动冲平）
```

- 核心等式：**缴费 = 公司收费 + 返还**；**公司应留存 = Σ缴费 − Σ返还**，与财务到账/开票对。
- 与早先「代收扣留」口径的差异：真实表是业务员全额上缴、公司再返——结算等式变形，
  收款表结构不变（`收款人类型`、金额、关联记录照旧）；「返还」在报名记录上由机器人按
  缴费 − 公司收费 算好写回。
- 开票：按公司收费口径开票（`开票状态` 进报名三维状态），结算单即 5.3 导出物。

### 5.2 结算核对规则

- **单人单据**：缴费 vs 关联收款合计 → 未收 / 部分收款 / 已收齐 / 超收（红）；已退有负流水冲抵；
- **单据自洽**：缴费 ≠ 公司收费 + 返还 → 红灯（拆分错）；公司收费为空但已缴费 → 红灯；
- **业务员维度**：每人"代收 → 已上缴 → 应得返还"三栏账，差额非零即亮；
- **集团/客户维度**：按期（参加日期）出结算单，公司收费合计 vs 开票金额 vs 到账；
- **自动红灯**：超收、负返还、已退但有正向收款、状态已参加但缴费未收齐、同记录当日重复收款、
  身份证校验位不过（复用 batch 基建）；
- **触发**：每天 18:30 自动发「结算日报」+ 指令「结算」即时出。

### 5.3 报告与导出（旧表三张手工衍生表 → 系统自动产物）

- **按期结算单**（替代 `6.24结算` 手工表）：按参加日期/班期分组，含 交公司费用 / 公司收费 /
  返还 / 是否开票 列 → Excel 附件发群；
- **按集团名单**（替代 `某集团报名人员名单` 手工表）：集团筛选视图，随要随导；
- **未参加培训名单**（替代 `某集团未参加培训人员` 手工表）：已报名但参加日期为空且班期已开 →
  自动进日报并可作为提醒素材；
- **结算日报**（发群）：今日新增报名 / 收款笔数金额 / 差异逐条 / 业务员小计 / 集团小计；
- **经营周报**（后置）：报名量趋势、报名→缴费转化率、业务员业绩榜、集团应收 Top5；
- **财务明细**：直接给多维表格视图权限，不传文件。
